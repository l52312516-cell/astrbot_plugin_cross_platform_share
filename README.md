# Astrbot 对话数据跨平台共享

项目地址：[GitHub 仓库](https://github.com/l52312516-cell/astrbot_plugin_cross_platform_share)

本插件把一个完整 UMO（A）的已有对话数据，单向复制给一个或多个完整 UMO（B）。每个 B 获得独立的 `conversation_id`；复制完成后，A 与 B 的新消息互不影响。B 原有对话会保留，新副本会成为 B 的当前对话。

适用场景包括把 QQ 群聊、私聊或其他平台的已有上下文交给新平台会话使用。它是一次性复制，不是实时共享，也不负责不同 AstrBot 实例之间的数据迁移。

## 版本与要求

- 插件版本：`2.4.0`
- AstrBot 版本：`>=4.16,<5`
- Python 依赖：`aiosqlite>=0.19.0`
- 需要 AstrBot 的 `ConversationManager` 和 `PlatformMessageHistory` 管理接口。

接口不可用时，任务会显示失败或部分完成；插件不会用自己的 SQLite 伪造 AstrBot 对话。

## 安装与首次使用

1. 在 AstrBot 后台通过 GitHub 仓库地址安装插件，或下载仓库源码并放入插件目录，目录名保持为 `astrbot_plugin_cross_platform_share`。随后加载或重载插件。
2. 打开插件详情中的 `settings` 管理页，点击“添加映射”。
3. 填写已有历史数据的 A UMO、接收副本的 B UMO，选择复制范围。
4. 点击“保存并开始复制”。任务会立即在后台排队，不必等 B 发送消息。
5. 在页面中查看进度与结果；复制完成后，B 即可在自己的副本中继续对话。

也可以在 AstrBot 插件配置页直接编辑 `clone_mappings_json`，但管理页更方便查看复制状态和错误。

## UMO 与映射

UMO 必须是完整的 `平台:消息类型:会话ID`，例如：

```text
aiocqhttp:GroupMessage:10001
telegram:FriendMessage:20002
```

平台、消息类型和会话 ID 均按完整字符串精确匹配。一个 A 可以映射多个 B；同一个 B 只能出现在一条映射中。A 与 B 可以属于不同平台，也可以是同一平台的不同会话。

管理页保存的 `clone_mappings_json` 格式：

```json
[
  {
    "source_umo": "aiocqhttp:GroupMessage:10001",
    "target_umos": [
      "telegram:FriendMessage:20002",
      "qq:FriendMessage:30003"
    ],
    "scope": "auto",
    "revision": 1
  }
]
```

| 字段 | 说明 |
| --- | --- |
| `source_umo` | A 的完整 UMO，复制来源 |
| `target_umos` | B 的完整 UMO 数组，可包含多个目标 |
| `scope` | 来源类型校验，默认 `auto` |
| `revision` | 复制批次的正整数，默认 `1` |

`scope` 可选值：

- `all`：复制该完整 A UMO 的对话，不校验消息类型。
- `group`：要求 A 的消息类型为 `GroupMessage`。
- `private`：要求 A 的消息类型为 `FriendMessage`。
- `auto`：自动识别 A 为群聊或私聊，未知类型会被拒绝。

这里的“全部”是指**所填 A UMO 下的全部对话**，并非该平台所有用户或所有群组。

## 复制内容和过程

插件读取 A 的全部 conversation，为每个 B 创建独立 conversation，尽量保留标题、Persona、原始消息顺序、用户和助手角色、工具调用、消息组件 JSON 及可用的 token 统计。A 当前选中的 conversation 会映射到 B 的新副本并设为 B 当前对话。

插件还会分页复制 `PlatformMessageHistory` 中的原始平台消息，把目标平台和会话标识改为 B；保留可用的内容、发送者和时间字段，不复用源数据库主键，并清空不能跨用户复用的 LLM checkpoint 引用。

保存映射后会立即启动后台任务。B 在任务未完成时发起 LLM 请求，会等待该 B 的复制锁并尝试补齐，避免并发创建重复副本。插件重载后也会恢复未完成任务。已完成的同一批次不会因再次保存或 B 再次发消息而重复复制。

复制完成后 A、B 不持续同步。A 后续新增的消息不会出现在 B，B 的消息也不会写回 A。B 原有 conversation 不会被删除；如果 B 后来手动切换到其他对话，插件不会在下次请求中强制切回副本。

## 再次复制：Revision

如果 A 的历史已有更新，需要重新给 B 一份快照，请在映射卡片中点击“重新复制一批”并确认。插件会自动增加 `revision`，为该映射的全部 B 创建一批新副本；旧副本和 B 原有对话都保留。也可以手动把配置中的 `revision` 改为更大的正整数后保存。

例如 Revision 1 已复制完成，A 后来增加了新消息；创建 Revision 2 后，B 会获得另一批新的独立 conversation ID。此操作不是在旧副本上持续追加 A 的消息。

## 后台管理页

管理页可以添加、编辑或删除映射，并显示：

- 当前任务、已完成、排队或执行中、需要处理的数量；
- 每个 B 的任务状态、阶段、对话和平台消息进度、尝试次数、耗时与错误详情；
- 分页复制历史及每批任务的详情；
- 源 conversation ID 与目标 conversation ID 的对应关系；
- 目标副本的只读对话预览，每页 20 条；
- “继续任务”和“重新复制一批”操作。

页面定期刷新状态，不会覆盖尚未保存的表单输入。预览会把消息作为文本展示，不加载媒体 URL 或二进制内容。

## 状态说明

| 状态 | 含义 | 可做什么 |
| --- | --- | --- |
| `pending` / 已排队 | 任务已建立，等待执行 | 等待后台处理或点击“继续任务” |
| `running` / 复制中 | 正在处理对话或平台消息 | 等待完成，查看阶段进度 |
| `partial` / 部分完成 | 已写入一部分，后续步骤出错 | 查看错误详情后点击“继续任务” |
| `complete` / 已完成 | 本批次已处理完成 | B 可使用独立副本 |
| `failed` / 失败 | 当前尝试没有完成 | 检查配置和错误详情后重试 |

任务通常经过检查来源、复制对话、复制平台消息、切换目标对话和完成几个阶段。`partial` 不等于复制结果全部无效：已创建的 conversation 映射和平台消息指纹会保留，重试时继续补齐。若映射已被修改或删除，旧历史任务仅供查看，不能继续按过时配置执行。

## 配置与数据位置

| 配置项 | 默认值 | 用途 |
| --- | --- | --- |
| `clone_mappings_json` | `[]` | A→B 映射；管理页会自动维护 |
| `storage_dir` | 空 | 插件元数据目录；为空时使用插件目录下的 `data` |

插件 SQLite 只记录任务、阶段、conversation ID 映射和平台消息指纹等恢复信息，不保存对话正文。实际对话内容仍由 AstrBot 原生会话存储管理。复制会让 B 看到 A 原有的对话内容，请确认目标账号或群组适合接收这些数据。

插件不提供 Parquet 导出、文件上传下载、加密传输或聊天命令管理功能。

## 常见问题

**保存后为什么暂时显示“未开始”？** 后台排队和页面轮询是异步的，稍后刷新状态查看。若没有填写 B UMO，不会创建任务。

**为什么显示“部分完成”？** 对话或平台消息已有部分写入，但后续步骤失败。打开任务详情看错误，修复原因后点击“继续任务”；无需手动删除已有副本。

**对话两次了为什么还没有复制？** 正常情况下保存映射就会启动。请检查映射是否已保存、B 的完整 UMO 是否精确匹配、任务状态和错误详情，以及 AstrBot 日志。B 的请求只会触发其对应 UMO 的任务。

**A 新增了消息，B 为什么没有自动更新？** 复制是一次性快照。使用“重新复制一批”创建新 Revision，旧副本会保留。

**B 原有对话会丢失吗？** 不会。插件创建新 conversation 并切换当前选中项，不删除 B 原有对话。

**提示 ConversationManager 或 PlatformMessageHistory API 不可用？** 当前 AstrBot 环境没有提供所需接口。请确认 AstrBot 版本和插件日志；插件不会用 SQLite 生成看似成功但 AstrBot 无法使用的假对话。
